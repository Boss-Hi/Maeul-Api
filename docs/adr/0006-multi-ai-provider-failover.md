# ADR 0006: 일정 생성 AI 제공자 다중화 (순서 기반 대체)

## Status
**Accepted** (2026-11-07) — ADR 0003 의 "Gemini 단일 제공자" 결정을 대체합니다.

일정 생성을 Gemini 하나에 의존하자 키 오류(`API_KEY_INVALID`)와 모델 수요 폭주(503 high demand)가 그대로 사용자 실패로 이어졌습니다.
그래서 일정 생성기를 **AI 제공자 단위(claude, gemini, test)** 로 나누고, 설정된 **제공자 순서**(`ai.providers`, 기본 `claude,gemini`)대로 시도해 **어떤 이유로든 실패하면 다음 제공자로 넘어가도록** 했습니다.
제공자마다 프롬프트 공통부와 일정 조립 로직은 공유하고, 호출 방식과 응답 형식 강제 방식만 다릅니다(Claude 는 structured outputs, Gemini 는 프롬프트 + 코드 블록 정리).

## Considered Options
- **설정으로 제공자 1개만 선택**: 단순하지만 한쪽 장애 시 수동 전환이 필요해 이번 문제를 해결하지 못함
- **"사용 불가" 오류(키 없음·재시도 소진·429)에서만 대체**: 400·파싱 실패는 제공자 고유 원인일 수 있어 다른 제공자에서 성공할 여지가 있으므로 모든 실패에서 대체하기로 함

## Consequences
- 같은 요청이라도 제공자에 따라 일정 품질과 비용이 달라질 수 있습니다. 어떤 제공자가 생성했는지는 로그(`[provider] 일정 생성 성공`)로만 확인할 수 있습니다.
- AI 키는 제공자별로 관리되며(`ai_api_keys.provider_type`), 같은 제공자의 키끼리만 돌려 씁니다.
- 일정 생성 요청 API 는 순서 안의 모든 제공자에 활성 키가 없을 때만 503 을 반환합니다.
